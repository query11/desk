## 背景

Desk 是 Windows 11 24H2/25H2 x64 的桌面美化工具：浮岛式任务栏和毛玻璃开始菜单。C#/.NET 10 宿主负责设置窗口、托盘和进程管理，
C++/WinRT 的 `DeskTap.dll` 注入资源管理器和开始菜单进程应用样式。设置窗口用 WPF 和 WPF-UI 4.3.0，共六个页面：
概览、外观方案、任务栏、开始菜单、显示器、设置。

上一轮（提交 `b705cda` 到 `19528aa`）已经整理过这个窗口：图库的筛选和状态保持、试用状态、显示器页的卡片布局、概览预览里的信息岛、
切换页面回到顶部等，说明在 [使用指南](THEME-MANAGEMENT.md) 的「界面细节」一节和 [TESTING.md](TESTING.md) 第 22 节。
本文列的是那之后复查代码和 CI 截图时发现的问题。**开始前先确认检出的代码包含提交 `19528aa`**（`git log --oneline | head`）；
如果不包含，说明这些改动还没有合并到你所在的分支，先告诉用户，不要在旧代码上重做一遍。

每一项都标了依据：「截图」表示在 CI 截图里直接看到，「代码」表示来自阅读代码、行为还没有运行确认，「未查明」表示只有现象。
来自阅读代码的项目，动手前先核对当前代码和触发条件；如果已经不成立，跳过并在结果里说明。

## 怎样验证（重要：这里不能运行界面）

开发环境通常是 Linux 容器，WPF 不能运行，只能编译。实际渲染要靠推送后 GitHub Actions 在 Windows 上的结果。

**本地（Linux）**

```bash
apt-get install -y dotnet-sdk-10.0        # Ubuntu 24.04 自带源里有；dot.net 的安装脚本所在主机通常被网络策略拦截
dotnet test tests/Desk.Tests -c Release   # 逻辑测试，Linux 可以运行，目前 140 项
dotnet build src/Desk/Desk.csproj -c Release
dotnet build tests/Desk.Ui.Tests -c Release -p:EnableWindowsTargeting=true   # 只能编译，不能运行
```

编译能发现 XAML 语法、不存在的 `SymbolRegular` 名称和接口不匹配，但发现不了布局和渲染问题。

**CI（Windows）**：每次推送都会运行 `.github/workflows/build.yml`，约 7 分钟。和界面有关的两步：

- `tests/Desk.Ui.Tests`（`dotnet run`）：不启动 Desk，用内存里的假数据驱动真实控件，检查交互和控件是否越界，输出截图到 `ui-appearance-…` 附件。
  新的交互请在这里加断言；它按 `AutomationId` 找控件。
- `tests/ui-smoke.ps1`：启动不带引擎的 `Desk.exe`，用 UI Automation 走遍每个页面（浅色宽/窄、深色宽），截图到 `ui-smoke-…` 附件，
  并在构建日志里打印每个页面所有带名字的控件的位置和大小（`----- layout: …`）。窄窗口下有控件超出窗口右边、页面打开时标题不在可见位置都会失败。

用 GitHub 工具读取运行结果和作业日志。**尽量看截图**：上一轮有两处问题（1 px 粗的进度条、比同排矮的按钮）只有在截图里才看得出来。
附件的下载地址在 `productionresultssaN.blob.core.windows.net`（N 每个附件都不同，见过 3、10、13、17、19），默认网络策略会拦截；
名为 `desk` 的云环境只放行了 `sa3` 和 `sa13`。下载被拦截时，可以向用户申请放行当次的主机；用户不同意或不在时，
用冒烟测试日志里的布局数据核对位置和尺寸，并在结果里写明「没有看到截图」。不要为了看截图去改 CI（例如把图片打进日志或推到分支）。

结果说明里把每一项的验证方式分开写：编译、自动化测试、看过截图、只有静态分析。没有在真实桌面（带引擎、多显示器）上验证的，照实写。

## 已经踩过的坑

- **页面每次导航都重新创建**（WPF-UI 默认不缓存页面）。要跨页面保留的状态必须放在页面之外：参考 `GalleryState`（`ThemeGallery.cs`）
  和 `ParameterSection` 里的 `Expanded`。测试会反复新建控件并期望初始状态，所以这类状态要能注入或按 key 选择启用，不能无条件用静态字段。
- **所有页面共用一个滚动区域**，`MainWindow.xaml.cs` 在导航后把它滚回顶部。页面内不要再套一层纵向滚动。
- `ui:InfoBar` 只有标题和正文，没有放按钮的位置；需要操作按钮时用 `Border` 自己搭（概览的 `OutdatedBanner`、主窗口的 `TrialBanner`）。
- `ProgressBar` 在 `Height="3"` 时指示条只有 1 px；试用横幅的倒计时条是用两列 `Grid` 自己画的。
- 隐式样式不作用于子类：继承 `CardControl` 等控件时要显式引用样式（见 `ParameterCard` 构造函数里的注释）。
- 只有图标的按钮比带文字的矮，要显式给高度（32）。
- 个别 `SymbolRegular` 能编译但渲染成错误的字形（见下面第 1 项）。新用的图标要在截图里确认。
- `tests/ui-smoke.ps1` 必须保持 UTF-8 **带 BOM**、LF 换行（Windows PowerShell 5.1 靠 BOM 识别中文）。用脚本改写这个文件时注意别丢 BOM。
- `Desk.Ui.Tests` 和 `ui-smoke.ps1` 依赖现有的 `AutomationId`、`x:Name`（`NavHome`、`MaintenanceExpander`、`ReapplyButton`、
  `Gallery.Apply.<id>`、`Displays.show`…）和各页的大标题文字。改名或改控件类型时同时改测试，并在提交说明里写清楚。
- `ThemeOption.cs`、`ThemeTrial.cs`、`Appearance.cs`、`Settings.cs` 等文件同时被 `tests/Desk.Tests` 直接编译（见它的 csproj），
  这些文件里不能引用 WPF 或 Windows Forms 类型。

## 约束

- 不修改 `src/DeskTap` 下的原生代码，不改版本号（`Desk.csproj` 的 `Version` 和 `src/DeskTap/src/version.h`）。
  宿主靠版本判断系统进程里是不是旧引擎，只改一边会让用户看到「重启资源管理器」的提示。
- 不新增 NuGet 依赖。
- 设置文件（`%APPDATA%\Desk\settings.json`，`Settings.cs`）新增字段要有默认值，旧文件能照常读取；不删除、不改名已有字段。
- 保留现有行为的可撤销性：参数修改走 `AppearanceHistory`，方案切换可以撤销，保存失败时保留原状态并提示。
- 文案是简体中文，口吻和现有页面一致：直接说明会发生什么，不用感叹号。引号在界面里用「」。

## 一、必须修复

### 1. 设置页「导出诊断」的图标显示成错误字形（截图）

`src/Desk/Ui/Pages/SettingsPage.xaml` 里 `导出诊断` 卡片用的 `DocumentArrowDown24`，在冒烟测试的 `…-3-设置.png` 里显示成一个类似「ɥ」的字符，
其余卡片的图标都正常。换成能正确渲染、含义相近的图标，并在新的截图里确认；顺便把各页截图里的图标过一遍，看有没有同类问题。

### 2. 冒烟测试的「深色」一轮实际是浅色（截图）

`ui-smoke-…` 附件里 `dark-wide-*.png` 全部是浅色界面，完整窗口的深色外观其实没有被测到（`Desk.Ui.Tests` 的深色截图是对的，因为它直接指定主题）。

已知事实：`ui-smoke.ps1` 的 `Start-Desk` 只写了注册表的 `AppsUseLightTheme`；`DeskApp.ReadLightMode`（`DeskApp.cs`）读的是 `SystemUsesLightTheme`，
用来决定任务栏材质的浅/深色数值，这是对的（任务栏跟随系统模式）；设置窗口的主题由 `UiHost.EnsureApplication` 里的
`ApplicationThemeManager.ApplySystemTheme` 和 `MainWindow` 里的 `SystemThemeWatcher` 决定，它读哪个值**没有核实**。

要求：

- 查清 WPF-UI 4.3.0 依据什么判断浅/深色。设置窗口应当和其他应用一样跟随「应用模式」（`AppsUseLightTheme`）；
  如果它现在跟随的是别的值，用户把 Windows 设成「系统深色、应用浅色」时窗口就会和别的应用不一致，这种情况要改对。
  任务栏和开始菜单参数继续按现有规则（系统模式、开始菜单配色设置）。
- 让冒烟测试的深色一轮真的是深色，并加一条断言（例如取截图里窗口背景的一个像素判断明暗），以后再变回浅色时测试会失败。
- 浅色一轮同理，确认运行机默认是深色时它仍然是浅色。

### 3. 图库每次变化都重建全部卡片，键盘焦点会丢（代码）

`ThemeGallery.BuildCards` 在每次搜索按键、切换分类、收藏、应用以及任何 `StateChanged` 时清空并重建所有卡片。推断的后果（先确认）：
用键盘操作时，点了星标或「应用方案」后焦点所在的按钮被销毁，焦点回到页面开头；应用方案期间卡片先全部禁用再全部重建，会闪一下。

要求：操作之后焦点留在同一张卡片的同一个按钮上（控件被替换时按 `AutomationId` 找回并重新聚焦）；与图库无关的设置变化不触发重建，
或者重建后界面状态不变。可以改成原地更新卡片，也可以保留重建但恢复焦点，选改动小、容易验证的做法。
`Desk.Ui.Tests` 里图库的测试假定搜索和点击是同步生效的（设置 `search.Text` 后立刻检查卡片数量），如果加防抖要同时调整测试。

验收：在 `Desk.Ui.Tests` 里加断言——给某张卡片的星标按钮设焦点并点击后，焦点仍在该方案的星标按钮上。

### 4. 概览的「可能有冲突」提示关不掉（代码）

`HomePage.Refresh` 每次都执行 `ConflictInfo.IsOpen = _app.Conflicts.Count > 0`，而提示是可关闭的（`IsClosable="True"`）：用户点了关闭，
下一次状态变化它又出现。记住用户对「这一组冲突程序」的关闭（窗口打开期间有效即可，注意页面会重建）；冲突程序的集合变了再重新提示。

### 5. 引擎无法运行时，概览的文字互相矛盾（截图）

缺少 `DeskTap.dll` 时（冒烟测试就是这种情况），标题旁的标签是「无法运行」，下面一行却写着「已启用 · 各部分的实际生效情况见下方状态。」，
开关也显示「已启用」。`HomePage.RefreshStatus` 里的 `SummaryText` 只看 `_app.Enabled`。让这一行跟随 `ShowState` 得出的整体状态：
无法运行、需要注意、正在连接、运行中、已停用各有一句说明当前情况和下一步的话（例如需要注意时指向下面的状态卡片和「维护与恢复」）。
开关表示的是用户的选择，保持不变。

## 二、应该改进

### 6. 不切换 Windows 模式也能调另一种模式的数值（代码）

「透明程度」「明暗统一」按浅色、深色分别保存（`ParameterInfo.PerMode`），但页面只能编辑 Windows 当前所处的那一种：
想调深色的数值得先把系统切到深色。`DeskApp.SetParameter`、`GetParameter`、`ApplyMaterialPreset` 都用 `IsLight(scope)` 决定读写哪一份。

在任务栏、开始菜单页的参数区加一个「正在编辑：浅色 | 深色」的选择，默认是当前生效的模式。选了另一种时：滑块、材质预设、单项重置和撤销
都作用于那一种；效果预览按所选模式绘制；并明确提示「当前桌面是另一种模式，这里的修改在切换后才看得到」。只有按模式保存的参数受它影响，
其余参数照旧。需要扩展 `IAppearanceEditor`（让读写可以指定模式），同时更新 `DeskApp`、`DisplayEditor`（`DeskApp.Displays.cs`）
和测试里的 `MemoryEditor`。显示器页是否提供这个选择由你判断，保持三处行为一致即可。开始菜单页现有的 `ModeText` 说明要跟着改。

验收：`Desk.Tests` 覆盖「编辑非当前模式只改对应的 `@light`/`@dark` 值、撤销只恢复那一份」；`Desk.Ui.Tests` 覆盖切换后滑块显示另一份数值。

### 7. 「效果预览」和其他预览不是一套东西（截图）

任务栏、开始菜单页的「效果预览」（`MaterialPreview.cs`）画的是一条彩色渐变上的玻璃条，概览和图库（`DesktopPreview.cs`）画的是
用户壁纸上的整个桌面。同一组参数在两种预览里看起来不一样，而且「效果预览」默认折叠、往下调滑块时会滚出视野。

改成一套：参数页的预览也用 `DesktopPreview` 的画法和当前壁纸（任务栏页突出任务栏区域，开始菜单页突出菜单），随滑块实时更新。
`DesktopPreview` 现在从 `ThemeOption` 读数值，参数页需要按「当前编辑的数值」绘制（包括第 6 项选的模式和显示器页的本屏数值），
需要给它一个按名称取值的入口。保留「效果示意」的标注和现有的 `Preview.<scope>` 展开器及其测试；模糊壁纸已经有全局缓存（按宽度 64 px 分档），
拖动「模糊」滑块时注意不要每一步都生成新位图而卡顿。能不保留 `MaterialPreview` 就删掉它。

### 8. 滑块旁的数值可以直接输入（代码）

`ParameterCard` 的数值只是文字。精确设置（比如把圆角设成 12）只能慢慢拖或按方向键。让数值可以点击后输入，回车或失去焦点时生效，
超出范围取边界、按步长取整，输入无效时恢复原值；带单位的显示格式（px、%）和「透明程度」的反向映射保持正确。键盘可达，读屏名称清楚。
窄宽度（内容区 412 px）下不能把滑块挤出卡片，`Desk.Ui.Tests` 的越界检查要继续通过。

### 9. 记住窗口的大小、位置和上次所在的页面（代码）

关闭窗口后 Desk 留在托盘，再次打开会新建一个 `MainWindow`：默认大小、屏幕居中、回到概览。记住上次的大小、位置、是否最大化和所在页面，
至少在 Desk 运行期间有效，最好写入设置文件。恢复时检查那个位置现在是否还在某块屏幕的工作区内（显示器可能已经拔掉、缩放可能变了），
不在就回到默认；现有的「不超过工作区」的限制保留。UI 测试通过 `new MainWindow()` 离屏渲染，不能依赖已保存的值。

### 10. 每页有两个叠在一起的大标题（截图，属于视觉取舍）

每页顶部固定着一个 28 px 的面包屑标题（「概览」），紧接着页面里又有一个 28 px 的大标题（「桌面，刚刚好」）和一行说明，
在 840 px 高的默认窗口里占掉约 150 px，导航栏本身也已经标出了当前页面。

建议的做法：去掉固定的面包屑标题（`MainWindow.xaml` 里 `NavigationView.Header` 的 `BreadcrumbBar`），保留页面里的大标题，
窗口标题和读屏仍能得到页面名称（`Page.Title`、导航项名称）。导航栏折叠成图标的窄窗口里也要能看出当前在哪一页。
这是外观上的取舍，**单独一个提交**，并在结果里给出修改前后的截图位置，方便用户否决后直接回退。冒烟测试的 `Assert-Title`
用页面大标题和它的纵坐标（≥150）判断页面是否从顶部打开，标题上移后要相应调整阈值。

### 11. 显示器页：说明「跟随全局」现在是什么，多屏时更容易选对屏幕（代码）

- 下拉框里的「跟随全局」看不出全局当前是显示还是隐藏。改成带出当前值，例如「跟随全局（显示）」。`IDisplaySettings` 现在不提供全局值，
  需要扩展接口，并更新测试里的 `MemoryDisplays`。
- 只有一块屏幕时，顶部是一个被禁用的下拉框，看起来像出了问题；这时直接显示屏幕名称和分辨率即可。
- 两块以上屏幕时，下拉框里只有设备名称和分辨率，同型号的两块屏幕分不清。按实际排列画出各屏幕的示意（位置在 `Screen.Bounds` 里，
  `DesktopDisplay` 需要带上它），点击选择，标出主屏和正在使用独立设置的屏幕；保留键盘可操作的方式和 `Displays.Select` 这个入口，
  或者同步修改测试。没有真实多屏环境，这一部分只能用 `MemoryDisplays` 验证，结果里写明。

### 12. 图库的成功提示改成会自己消失的（代码）

图库里「方案已切换」「已导入」「已导出」用的是页面内常驻的 `InfoBar`，要手动关；其他页面的成功反馈都是底部自动消失的提示（`UiHost.Toast`）。
成功用 `UiHost.Toast`，「正在应用…」和错误继续用页面内的 `InfoBar`（错误需要留着看）。`Desk.Ui.Tests` 里图库是脱离主窗口测试的，
`UiHost.Toast` 在没有窗口时什么也不做，测试里对错误提示的断言保持有效。

### 13. 托盘菜单（代码，无法在 CI 里看到）

`DeskApp.Tray.cs` 的菜单是默认外观的 `ContextMenuStrip`：深色模式下仍是浅色；「主题」子菜单把所有方案平铺成一列，不分收藏、推荐和个人方案，
试用进行中也看不出来，而且列的是 `GetThemes()`，顺序和图库不一致。

要求：子菜单的顺序和分组与图库一致（收藏在前，推荐、其余内置、我的方案之间加分隔），复用 `GetAppearanceOptions()` 的排序；
