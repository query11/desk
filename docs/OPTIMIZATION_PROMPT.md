## 目标与工作方式

你正在维护 Desk，一个 Windows 11 24H2/25H2 x64 桌面美化工具。C#/.NET 10 宿主负责设置、托盘和进程管理，C++/WinRT 的 `DeskTap.dll` 在资源管理器和开始菜单进程中应用样式。

本次目标是提高故障恢复能力、降低无效开销，并让各个主题独立保存用户调整。按以下五项推进，优先完成前三项稳定性修复。

开始前阅读 `README.md`、`docs/PLAN.md`、`docs/TESTING.md`、`.github/workflows/build.yml` 和适用的 `AGENTS.md`，检查工作区已有修改。使用当前检出的仓库；云任务已经隔离，除非用户明确要求，不创建额外 worktree。基于实际代码复核下面的调用链，再实施最小且完整的修改；如果代码已变化，按实际情况调整。

以下问题来自代码审查。其中“主题参数串用”已通过直接运行现有 `Theme.cs` 和真实主题文件复现；Windows 注入、初始化和渲染问题尚未在 Windows 实机复现，性能收益也尚未测量。测试报告必须区分静态分析、自动化验证和 Windows 实测。

## 1. 修复崩溃保护停用后仍可能继续注入的问题（最高优先级）

重点文件：

- `src/Desk/TargetManager.cs`：`Tick`、`TickExplorer`、异步完成回调。
- `src/Desk/DeskApp.cs`：`OnExplorerChanged`、`SetEnabled`、`Tick`。

当前调用链：`TickExplorer(inject: true)` 发现新的资源管理器 PID，同步触发 `ExplorerChanged`。当重启次数达到保护阈值时，`OnExplorerChanged` 调用 `SetEnabled(false)`。但回调返回后，外层仍使用此前的 `inject=true`，可能再次提交注入任务。

需要实现：

- 在真正提交注入工作前，以当前启用状态和保护状态作决定，消除同步事件重入导致的过期判断。
- 检查手动停用、退出、目标 PID 变化、重新应用时的同类问题。对尚未开始的任务进行取消或失效处理，异步完成回调不得覆盖新一轮状态。
- 明确已经开始执行的原生调用无法立即撤回时如何处理；保护触发后不再安排新的注入，也不因旧任务回调重新启用美化。

验收：模拟连续重启达到保护阈值，确认当前这一轮和后续轮询均不再提交注入；覆盖停用发生在重入回调、任务排队、异步返回期间的情况。用户主动重新启用后，应能正常重新连接。

## 2. 区分开始菜单注入失败与挂起等待，恢复自动重试（最高优先级）

重点文件：

- `src/Desk/TapInjector.cs`：`InjectWithRemoteThread`。
- `src/Desk/TargetManager.cs`：`TickStartMenu`、`ShouldAttempt`、`Finish`。

当前注入接口只返回布尔值。打开进程、分配内存、写入路径或创建线程失败，与远程加载线程尚未执行，都可能返回 `false`。宿主在未发现 DLL 时统一标记为 `Pending`；此后只轮询 DLL 是否出现，不再尝试恢复。

需要实现：

- 用明确的结果类型区分加载成功、真正失败，以及已经创建加载线程但仍在等待。记录对应阶段和错误码，便于诊断。
- 真正失败进入有退避的重试流程；“等待开始菜单唤醒”不能掩盖失败。
- 等待状态应有可追踪的任务身份和后续状态检查。不要仅因超时就反复创建远程线程，也不要在原线程仍可能访问路径时释放远程内存；任务完成或目标进程退出后妥善清理资源。
- 用户停用、目标进程退出或换 PID、手动重新应用时，处理旧任务和旧回调，避免重复加载及状态错乱。

验收：分别模拟打开进程失败、内存操作失败、创建线程失败、加载失败、进程挂起后唤醒和目标退出。暂时性失败解除后能够自动恢复；挂起等待不会产生重复注入；UI 的等待、失败和恢复状态与实际结果一致。

## 3. 增加引擎就绪与配置应用反馈，并允许初始化失败后恢复（最高优先级）

重点文件：

- `src/Desk/DeskApp.Api.cs`、`src/Desk/TargetManager.cs`、`src/Desk/RuntimeWriter.cs`。
- `src/Desk/Ui/Pages/HomePage.xaml.cs`。
- `src/DeskTap/src/dllmain.cpp`、`install.cpp`、`tap.cpp`、`watcher.cpp`、`engine.cpp`、`config.cpp`。

当前宿主仅凭 DLL 已加载就显示“已生效”。XAML 初始化实际发生在后续异步流程中，重试结束后失败只写日志；DLL 已固定在进程中，初始化前创建的进程互斥量也继续存在。再次加载同一个 DLL 不会重新执行初始化，加载其他版本又会被单实例保护挡住，因此“重新应用”不能修复这种失败。

需要实现：

- 在宿主与引擎之间建立轻量、可诊断的状态反馈，清楚区分“DLL 已加载”“引擎初始化中”“引擎可用”“当前配置已处理/应用”和“失败”。UI 仅在有对应证据时显示“已生效”。
- 定义“已应用”的准确含义。目标界面尚未创建、规则没有匹配目标或应用出错时，不能仅靠收到配置就宣布成功。
- 状态应能关联当前目标进程实例、引擎版本和配置序号，拒绝旧进程、旧配置和旧任务的过期结果。传输方式按现有架构选择，兼顾开始菜单 AppContainer 的访问权限和原子更新。
- 支持受控的初始化重试和手动恢复，同时保持每个目标进程只运行一个引擎。正确处理部分初始化成功，避免重复注册回调、重复安装 hook、并发初始化或为了重试直接取消单实例保护。
- 兼容目标进程仍运行旧版 DLL 的情况：显示明确的升级/恢复提示，不把旧模块存在当成新协议已就绪。失败恢复不能变成循环强制重启资源管理器。

验收：注入成功但 XAML 初始化失败时，界面不再显示“已生效”；依赖恢复后能够重新初始化并应用配置；缺失或过期的状态不能产生假成功；目标重启、快速连续修改配置、旧版 DLL 共存和重新应用均有明确结果。

## 4. 降低滑块调节和信息岛的重复工作（性能优化）

### 4.1 复用模糊效果资源

重点文件：`src/DeskTap/src/engine.cpp`、`values.cpp`、`blur.cpp`、`blur.h`，以及宿主的 `ApplySoon`。

当前样式参数变化后会重新创建 `DeskBlurBrush`，并创建新的 `CompositionEffectFactory`；噪声虽然缓存了图像数据流，但仍会再次加载 `LoadedImageSurface`。拖动滑块时可能反复构造相同的效果结构。

需要实现：

- 区分效果结构变化与数值变化。效果结构不变时优先更新可修改的效果属性，复用工厂和噪声图像资源。
- 缓存遵守 Compositor、线程和设备的生命周期约束，不能跨不兼容的 Compositor 或线程共享对象。控制缓存大小，并处理断开、重连、设备变化和资源释放。
- 保持不同元素之间的参数隔离，以及现有明暗模式、HostBackdrop、颗粒、节能/关闭透明效果回退和退出还原行为。
- 保留滑块实时反馈，避免把优化变成必须松开鼠标才生效。

验收：在同一设备和主题下，对比连续拖动模糊、着色浓度、明暗统一等滑块时的效果工厂创建次数、噪声图像加载次数、CPU/GPU 或 UI 帧时。反复切换主题和模式后资源占用应稳定。只能报告实际测得的收益。

### 4.2 按需在后台采样信息岛指标

重点文件：`src/DeskTap/src/monitor.cpp`。

当前采样器无条件采集 CPU、内存和网卡信息，计时器在任务栏 XAML UI 线程执行。关闭单项指标只隐藏控件，仍继续采样、格式化并更新这些隐藏控件。

需要实现：

- 只采集当前需要的指标；关闭网速显示后停止为它枚举网卡，关闭整个信息岛后停止不必要的周期工作。
- 将可能阻塞的采样移到后台，向 UI 线程投递结果；后台线程不访问 XAML 对象。多任务栏共享可用样本，避免每个显示器重复采集。
- 只更新需要显示且数值或样式实际变化的控件，避免积压过期采样结果。
- 重新开启 CPU/网速采样时重建差值基线，正确处理网卡变化、休眠恢复和目标对象销毁，避免异常数值与失效回调。

验收：只显示内存时不采集网速和 CPU；关闭信息岛后不残留无用采样任务；重新开启和休眠恢复后数值正常。记录优化前后的采样次数、后台占用和 UI 线程耗时。

## 5. 按主题独立保存用户参数（体验优化）

重点文件：

- `src/Desk/Settings.cs`、`DeskApp.Api.cs`、`DeskApp.cs`、`Theme.cs`。
- `src/Desk/Ui/ParameterSection.cs` 及主题选择相关页面。

当前所有主题共用 `_settings.Overrides`。已复现：将普通浮岛主题的浅色 `islandOpacity` 调到 `0.8`，再切换到默认值为 `0.3` 的高通透主题，最终编译出的材质仍然使用 `0.8`。

需要实现：

- 按主题身份分别保存参数，沿用当前主题 ID 和同名用户主题覆盖内置主题的解析规则。继续支持 `name@light`、`name@dark` 及通用参数。
- 切换到没有自定义参数的主题时使用其默认值；切回已调整过的主题时恢复该主题的调整。
- “恢复默认”只清除当前主题、当前页面参数组的覆盖值，保留现有同时清除该组通用及明暗覆盖值的行为，不影响其他主题或另一页面。
- 为旧设置中的全局 `Overrides` 实现一次性、可重复执行而不产生副作用的迁移。默认只归入旧设置选择的主题；无法确定归属时保留可恢复的数据，不将旧覆盖值复制到所有主题，也不静默丢弃。
- 保持设置文件原子保存和主题 JSON 兼容，避免用户主题临时不可用或加载失败时误将参数迁移到回退主题。主题加载与 UI 刷新后，滑块数值、重置按钮和实际应用值保持一致。

验收：覆盖 A 主题调整→B 使用默认值→B 独立调整→切回 A、程序重启、明暗切换、按页面重置，以及旧设置迁移执行两次的结果。使用仓库中的普通浮岛和高通透主题验证 `0.8` 与 `0.3` 的示例。

   dotnet restore src/Desk/Desk.csproj -r win-x64

   dotnet publish src/Desk/Desk.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true --no-restore -o dist/Desk
