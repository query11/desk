# Desk 0.4.4 本地改进记录

基于用户正在使用的发布包提交 `dc1f3f4aa534e15514cff0837d5285f5ffddb335`，本地分支为 `codex/blur-compatibility`。
开始开发时 GitHub 默认分支仍是较早的 v0.3，因此修复以发布包对应提交为基线。本文记录 0.4 系列的历史改动，当前功能见 [0.6.0 使用指南](THEME-MANAGEMENT.md)。

## 已修复

1. **默认主题开启颗粒后毛玻璃退回纯色。** 用户当前运行日志中，任务栏与开始菜单均记录 `80070057`。
   颗粒合成与最终着色合成都使用默认名称 `CompositeEffect`，违反 Composition 对非空节点名称唯一性的要求。
   现在效果节点默认不命名，只有需要按名字访问的节点显式命名。
2. **动态着色属性类型错误。** 独立复现中，`InsertVector4("Tint.Color", ...)` 返回 `80070057`。
   Flood 的颜色现在使用 `COLOR_TO_VECTOR4` 映射，动态调节使用 `InsertColor`。
3. **外观降级仍显示绿色成功。** 增加当前纯色降级画刷的状态报告；渲染失败显示「部分生效」和错误码，
   系统节能或关闭透明效果显示「已生效 · 纯色背景」及原因。样式应用失败也改为警告状态。
   只报告当前故障，恢复或释放画刷后清除。
4. **测试未覆盖真实效果创建。** 新增 Windows Composition 回归程序并接入现有 GitHub Actions，
   防止仅靠纯逻辑测试通过而遗漏实际渲染失败。
5. **开始菜单仍显示实心灰色。** 后续实机截图确认：效果创建成功并不代表取到了有效的背景。
   三个内置主题的 `menuMaterial` 现在明确设置 `BackdropSource="Backdrop"`，与该电脑上开始菜单原生 AcrylicBrush 的来源一致，
   避免 `Auto` 在开始菜单进程里选用 `HostBackdrop`。热重载后，截图确认后方窗口的模糊轮廓可见。
   本次同时备份并调整当前主题的开始菜单参数：模糊 18、浅色着色 0.12、浅色明暗统一 0.2、颗粒 0.012、饱和度 1.15。
   调整前设置保存在源码目录的 `build/settings-before-start-transparency.json`。

## 0.4.2 外观设置

- 任务栏图标默认由原先的 24 px 调为 28 px，按钮最小宽度 48 px；根据实机反馈从最初试用的 32/52 回调。
  「任务栏 → 图标大小」可选 24–36 px，按钮宽度随之联动。数值为逻辑像素，会跟随 Windows 缩放。
- 任务栏、开始菜单提供「通透 / 均衡 / 清晰」材质预设；保留当前圆角、尺寸以及另一页的设置。
- 增加随参数变化的材质示意预览，明确标注「效果示意」，实际效果仍以桌面为准。
- 增加最多 30 步会话内撤销，连续滑块输入会合并；恢复默认也可以撤销，关闭程序后历史不保留。
- 「保存为我的方案」将任务栏和开始菜单当前的浅/深色外观保存为独立用户主题，在概览页切换。
- 「透明程度」越高着色越淡；明暗、饱和度、颗粒和上下留白收进默认折叠的高级设置。
- 保留 0.4.1 的毛玻璃修复和开始菜单背景来源设置。

## 0.4.3 尺寸、空间适配与紧凑界面

- 图标大小和按钮占位宽度独立调整。保留默认 28 px 图标、48 px 按钮宽度；修改图标不会覆盖用户选择的间距。
- 上下留白回到基础设置；图标大小、透明程度排在最前。说明移入悬停提示，预览默认折叠，材质预设缩成一行。
- 每项参数都有独立重置按钮，重置仍可撤销；不影响其他项、另一页和其他主题。
- 两个浮岛主题启用自适应布局：按各自 XAML 根的逻辑宽度、托盘实际位置和信息岛占位计算按钮和监控内容的空间预算。
  先缩小按钮间距，再只显示首要监控项（网速优先，其次 CPU、内存），极窄时暂时隐藏信息岛，剩余应用由系统溢出菜单承接。
  不改用户保存的间距或监控勾选；空间恢复后自动还原。恢复监控项留有 24 px 余量，防止临界宽度来回切换。
- 布局事件合并到 120 ms 后处理，没有独立轮询线程。按钮间距仍由原样式引擎保存和还原，停用或切换整条布局时撤回调整。
- 仅在主题包含 `adaptiveLayout=1` 且当前为浮岛模式时启用；自定义旧主题和整条模式沿用原有布局。
- 此版更新了原生引擎，首次从 0.4.2 升级需重新加载资源管理器和开始菜单进程。

## 0.4.4 提前溢出修复

- 0.4.3 在当前电脑 8 个按钮时错误出现「…」，应用被挤进溢出菜单。撤回自适应外层几何后，用户确认恢复。
- 真实测量表明，仅取消 MaxWidth 仍不够：动态 Margin 会使中间栏从 400 缩成 346 逻辑像素，`overflow=0` 变为 `1`。
  因此不再接管 TaskbarFrame 的 Margin 或 MaxWidth，保留主题中已经验证的外层布局，自动调整仅作用于按钮间距和自有信息岛。
- 新增实际栏体宽度、按钮数量、溢出按钮状态的诊断日志。引擎 `errors=0` 只表示样式写入没有报错，不能证明图标没有被挤进溢出菜单。
- 当前电脑实际验证：自适应开启后 `screen=1560 frame=400 buttons=8 spacing=48 overflow=0`，与关闭自适应的正常宽度一致。
- 同时段系统记录过一次 Explorer 的 Windows.UI.Xaml.dll 异常；现有事件信息不足以确定具体原因，不将修复后短期无错误等同于长期稳定性结论。

## 验证

- .NET 逻辑测试：117 项通过，包括独立尺寸编译、布局配置及紧急恢复、撤销隔离、预设范围及个人方案编译一致性。
- 新的独立 WPF 验证程序：8 组场景通过，覆盖任务栏/开始菜单、浅/深色、760/460 px 内容宽度，
  检查预设选中、透明度映射、撤销、重置和控件边界；16 张折叠/展开截图已生成并抽查。
  该程序不启动 Desk 宿主、不注入系统进程、不修改用户设置或 Windows 主题。
- C++ 引擎逻辑测试：31 项通过，覆盖正常布局、8 按钮桌面、收紧间距、监控降级/恢复、防抖、窄屏和无托盘布局。
- 真实 Windows Composition 接口：4 组通过，覆盖颗粒开/关、静态/动态属性。
- Desk.exe 与 DeskTap.dll 已在本机编译。
- 后续实机复核：当前电脑浅色模式下，开始菜单由实心灰色恢复为能透出后方窗口的毛玻璃；主题相关测试 9 项通过。
  尚未完成深色模式、多屏、不同缩放和任务栏各状态的全面视觉验收。

## 后续最值得做的改进

1. **扩大自适应布局实机覆盖。** 0.4.3 已实现动态空间分配，继续在不同缩放、多屏、应用标签和大量固定应用的环境下验证。
2. **按显示器判断最大化状态。** 当前文档明确只看主任务栏所在显示器。
   建议每个任务栏独立判断，避免主屏最大化影响副屏浮岛。
3. **渲染能力与资源表现的可观测性。** 在诊断里展示正常模糊、系统纯色、异常降级三个状态，并测量待机、
   拖动滑块、睡眠唤醒的 CPU/GPU 与工厂重建次数，确认性能收益。此次已先补齐降级状态。

## 使用修正版

先在旧版托盘菜单选择「退出并还原」，再启动修正版目录里的 `Desk.exe`。
本机 0.4.2 包曾复用 0.4.1 修正版 DLL；0.4.3 使用新引擎，需要重新加载系统界面进程。
从原始版本升级时，旧 DLL 会留在已有系统进程内；如果首页提示旧版引擎，请保存工作后按提示重启资源管理器，
开始菜单仍提示旧版时可在方便时注销并重新登录。
应用沿用原有设置。原始发布包保留，便于回退。

源码与回归测试纳入仓库，构建产物由 GitHub Actions 提供；本地设置备份和诊断日志不包含在仓库中。
